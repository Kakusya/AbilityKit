## Cooking 真实 UDP LAN 最小纵切

### 目标
新建一个独立的纯 .NET Cooking UDP 任务，以 LiteNetLib `ReliableOrdered` UDP 验证 listen host（含本机玩家）与远端客户端共用既有权威队列。分阶段产出 codec 契约、真实 UDP loopback、同机跨进程 harness，以及可由两台物理 PC 执行的 LAN 验收入口。

### 约束
- 不创建本地分支。
- 不恢复已归档的 Cooking P1/P6 task；建立新 task。
- 不实现或修改 Cooking Unity 范围。
- 不将 Cooking 接入 Orleans；只借鉴其生命周期、超时、进程管理和 artifact 模式。
- 两机 LAN 没有实际执行不得表述为通过；不自动改防火墙/网络配置。
- 不实现自动重连、endpoint rebinding、主机迁移、NAT/WAN、存档退出语义或预测/rollback。

### 实施
1. 创建 Trellis task，完成 PRD、设计、实施清单和 context manifests，引用 ADR-0001、ADR-0002、Cooking P1/P6 规范、progress 和 successor backlog；得到本次批准后进入 `in_progress`。
2. 新增 `AbilityKit.Game.Cooking.Udp`、`.Tests`、`.UdpHarness` 纯 .NET 项目。UDP 层使用 LiteNetLib 2.1.4，提供最小 host listener 和 client，独立于通用 LiteNet client 与 Orleans。
3. 定义版本化 datagram envelope：schema/protocol/message kind/correlation、scope/epoch/config identity，以及 handshake、command/result、baseline/delta、resync/loss 等消息。baseline/delta payload 携带完整 `CookingSnapshot`，并在 client projection 侧校验 canonical hash。
4. 用单线程 host dispatcher 串行调用 `CookingSessionAuthority`。LiteNet receive callback 只复制、解码和入 immutable queue；host-local 输入也经同一 facade/dispatcher。
5. 编写 codec、错误拒绝、身份绑定、sequence/baseline、dedup、loss、lifecycle、stop/restart、并发回调线程隔离和真实 UDP loopback 测试。
6. 新增 host/client harness 和 PowerShell runner，用唯一端口、readiness/timeout、受控进程清理、状态 hash/JSONL/报告 artifacts 完成同机跨进程验证。
7. 扩展 measurement 以区分 loopback、同机跨进程、两 PC LAN，分开记录 encode/send、receive/decode、apply、authority ingress-to-commit；阈值保持 `UNSET`。
8. 增加手动 `cooking-udp` P1 门禁并同步测试门禁文档；运行针对性测试、该门禁和适用的既有 Cooking tests。两 PC LAN 作为单独人工环境出口，记录未运行或真实证据。

### 验收
- Host 本机玩家和远端 UDP client 完成握手、绑定、baseline、共享权威命令、result/delta 与一致 state hash。
- 错误 key/protocol/config/scope/epoch/sequence、过大/损坏包、重复命令、关闭和断线均有稳定拒绝与诊断。
- `CookingSessionAuthority` 不在 UDP 回调线程被访问。
- Loopback 与同机跨进程 artifacts 明确标注拓扑；不替代两物理 PC LAN。
- Cooking Unity、Orleans 和未授权产品语义不被改动。
