## Concrete routing: two raw sockets per physical remote route

For route R, bind IPv4 loopback frontend F_R and loopback upstream U_R on separately allocated ephemeral UDP ports. Client sends to F_R. Relay copies each received datagram and sends unchanged bytes from U_R to the actual owned Host backend B. Backend replies arrive at U_R; relay sends unchanged bytes from F_R to the verified original client socket C_R. Host sees U_R; client sees F_R. Relay never calls LiteNet, strips headers, decodes business payload, emits ACK/ping/connect messages, merges/fragments packets or mutates bytes.

Pin upstream accepted source to exact B; reject/count any other source. Pin frontend source to exact C_R. Initially accept only the first loopback candidate after wrapper has identified the owned Client PID; before forwarding verify its UDP source port belongs to that PID with scoped read-only Get-NetUDPEndpoint (including wildcard-bound sockets that send via127.0.0.1). Retain actual endpoint/PID verification artifact. If this capability is unavailable, stop P0 as endpoint provenance NOT_VERIFIED; do not accept any arbitrary loopback sender. This is scoped inspection of launched process sockets, not LAN scanning.

Never repin an active route when a different source appears. A legitimate rebind opens a NEW route with fresh F_R/U_R and a new physical client socket; wrapper supplies that frontend only through trusted network control. Old route remains isolated until drained/retired; its bytes cannot be delivered to new C_R. This prevents old-generation packets and changed LiteNet source ports being accidentally mapped to the new peer. No assumption that reliable disconnect/connect reuse of one upstream port is transparent.

Bounds: at most4 created routes/8 sockets per experiment, at most2 concurrently open routes during controlled replacement. Normal profile uses initial generation1 route and post-load recovery generation2 route. Tests reject route5 and concurrent route3. Retired route traffic is counted separately as RetiredRouteRejected, not planned impairment loss. Both front/upstream ports must differ from backend and from every still-owned route port. Every actual connect records participant, generation, client socket, relay frontend/upstream and backend endpoints.

## Deterministic scheduler and resource bounds

Single relay owner event loop uses its owned nonblocking sockets and two due-time priority queues per route/direction; no unbounded Task.Delay per datagram. Drain readable sockets with a bounded per-iteration quota (256 datagrams), then process due sends and control queue. One incoming buffer per socket is copied into owned payload bytes before queueing/decision. IPv4 payload cap65507; oversized/truncated receives are errors, not impairment loss.

Global scheduled cap64MiB payload bytes and65536 datagrams across routes/directions, plus finite fixed socket buffers whose actual OS granted sizes are reported. Queue limit checks occur before admission; limit-1/limit/limit+1 controls prove no leak. Overflow, socket error, unknown approved endpoint loss or payload-length mismatch FAILS the configured experiment; retain first error/counters and stop only owned resources. Never attribute queue overflow or OS receive loss to selected1/5% loss. Report observed socket receive/drop diagnostics when available and their limits; absence of a counter is not zero kernel loss.

Each received datagram obtains monotonically increasing route/direction index and current policy epoch. For each direction choose loss by independent seeded PRNG draw over10000 basis points, threshold100/500; next independent draw selects integer jitter -20..20. Fixed implementation algorithm proposed SplitMix64 with documented unsigned overflow and bounded integer mapping; unit tests freeze exact vectors. Seeds derived by SHA256 of length-delimited tags(profile,repeat1..3,direction,route) plus fixed base `cooking-relay-v1`; use first8bytes big-endian and record base/derived seeds. Seed reproducibility means deterministic decisions for a given index, not repeatable live network timing or exact realized loss rate. Three repeats use distinct repeat-tag seeds.

Compute requested delay=max(0,D+jitter), due=received Stopwatch ticks+delay. Priority=(due,index); jitter is allowed to reorder. Count forwarded index lower than previously forwarded max as observed reorder, without silently restoring original order. No duplication, corruption or bandwidth cap in this matrix. Bernoulli decisions cover ALL raw UDP datagrams in BOTH directions, including LiteNet reliable acknowledgements, ping, retransmitted data, connect/disconnect and fragment datagrams occurring in armed phase. Relay never identifies a logical application message.

Maximum queue residence5s (separate from requested delay max170ms) and whole relay lifespan420s proposed. Delayed socket writability counts are separate; a datagram failing residence/deadline fails the experiment instead of being silently discarded. Successful forwarded count increments only after SendTo returns the original payload length. Maintain rolling payload length/hash checks for received→forwarded entries, counters for every datagram, and bounded diagnostics (first4096 decisions plus ring4096 anomalies; truncated trace flagged). Counters are complete despite bounded trace. No raw packet/credential/token dump is required.

## Trusted control plane and genuine phase barriers

Wrapper owns redirected stdin/out of all three launched processes. Prefer typed newline JSON controls/events, max16KiB per line, monotonic control sequence and unique run nonce. Relay accepts only PrepareRoute/Arm/Off/Stats/RetireRoute/Stop with validated profile and bounded parameters. This controls proxy forwarding policy ONLY. It cannot create a Host, enqueue a game command, set Ready, change a baseline or grant participant actions. A side-file alternative must preserve the same nonce/sequence/atomic-write boundary; filesystem messages are not gameplay authority or command receipts.

Driver telemetry contains actual instance/scope/config/MVID/participant/generation/current baseline identity+validated full hash/Ready and phase receipts, never rebind token or credential. It is derived from real public state; wrapper validates it before sending scheduling continuations. Host continues normal owner pumping while awaiting control; Client continues peer polling/ACKs. Do not block owner on synchronous Console.ReadLine, freeze business time to wait for proxy or call Tick from relay/control reader. Controls cannot accept arbitrary game operation payloads.
