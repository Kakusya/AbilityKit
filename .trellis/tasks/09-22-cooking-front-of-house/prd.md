# 前厅询问、洗碗与小关时间结构

> 状态：`planning`。本文件只记录需求与验收，不授权实现。实现须等最终规划摘要被明确批准，并经 `task.py start` 进入 `in_progress`。

## Goal

一位固定伙伴在营业时间里按队列走到桌边询问，问完才开单；空闲时去洗脏碗。小关先走完营业时间，再走完收尾时间，并且顾客都离席，才算成功。收尾不再来新顾客。没做完的订单随顾客超时离席记为未满足，但不让这一关失败。

用户价值：现在开单和洗碗都是测试直接注入。09-19 已经定过「NPC 问完才开单、空闲才洗碗、营业加收尾走完才成功」，这些节奏还没有运行对象。

## Background

产品决定来自 [`09-19-cooking-gameplay-business-discussion/prd.md`](../09-19-cooking-gameplay-business-discussion/prd.md)。当前代码事实如下。

- `OpenOrder` 是前厅注入缝隙：模板必须存在，订单身份不能重复。它不是玩家命令。
- `CompleteWash` 是另一条注入缝隙：脏碗洗干净后回到干净碗池。提交成功时，若接了 `ICookingBowlWashingPort`，会发出洗碗请求，但没有人占用 tick 去洗。
- 订单只有 `Open` 和 `Completed`。没有「未满足后关闭」的路径。
- 小关生命周期已经能成功收口、失败重开、交接厨房。成功条件仍由调用方直接给出结局，不是由营业和收尾时间推出来的。
- 固定伙伴人数暂定 1。失败条件、收益、评价和伙伴成长仍推迟。本任务不发明这些公式，也不做可见顾客实体。

## 这一串包含什么

这一个任务覆盖已经定过、并且现有开单/洗碗缝隙能接上的四件事。

1. 顾客占桌：营业时间按配置间隔到店并占一张空桌。收尾不再到店。
2. 询问：唯一伙伴空闲时按到店顺序走到桌边，停留配置的 tick 后开单。问的时候伙伴被占用。久等不惩罚。
3. 洗碗：没有询问要做时，伙伴按脏碗产生顺序去洗，洗完调用现有清洗完成。
4. 时间结构：营业 tick 走完进入收尾；收尾里已入座顾客吃完或超时后离席；全部离席才成功。未满足订单留下记录，不产生收益字段。

## Requirements

### R1 一位伙伴，一条队列

- 开局就有一位伙伴。没有招聘、换岗或人数变化。
- 询问和洗碗共用这一个伙伴。有待询问的桌子时先询问，没有才洗碗。
- 同一类任务按产生顺序处理。不引入优先级。
- 伙伴正在询问或洗碗时，不并行开始另一件。

### R2 问完才开单

- 顾客占到空桌后进入待询问，不立刻出现在订单簿。
- 伙伴走到该桌并停留配置的询问 tick 后，用现有 `OpenOrder` 开出该桌的订单。
- 没有空桌时，新顾客不入座，也不排队加塞到已有桌子前面。
- 顾客久等只是占着桌子，不扣分，不失败。

### R3 空闲才洗碗

- 玩家提交成功后，脏碗进入洗碗队列。
- 伙伴没有待询问桌子时，按队列取一只碗，占用配置的清洗 tick，然后走现有 `CompleteWash`。
- 干净碗池已满时这一只不洗完，队列保持，厨房不变坏。
- 伙伴正在询问时，不把洗碗插到询问前面。

### R4 营业、收尾、离席

- 小关从营业开始。营业期间按配置间隔尝试来一位顾客。
- 营业 tick 走完后进入收尾。收尾不再来新顾客。
- 已开单的顾客占桌用餐配置的 tick 后离席。没有在时限内吃到的顾客在配置的等待上限后离席，订单若仍是 `Open` 记为未满足。
- 收尾阶段全部顾客离席后，这一关可以成功结束。营业没走完不能成功。还有人坐着不能成功。
- 未满足不是失败。本任务不定义失败条件，也不调用失败重开。

### R5 关末收口

- 小关进入成功收口时，正在询问的顾客照常开出订单，正在洗的碗照常变干净。
- 这些收口不留下「做到一半」的伙伴任务。
- 成功交接仍清除本关订单。未满足记录属于本关，不带进下一关厨房。

## 明确不做

- 不发明收益、评分或评价数字。
- 不做伙伴成长、名字展示、聊天或岗位切换。
- 不做可见顾客、餐桌实体或 Unity。
- 不定义失败条件。
- 不改结算列表文件和大关检查点的字段。

## Acceptance Criteria

- [ ] 营业中按间隔占空桌；没有空桌不入座；收尾不再来人。
- [ ] 问完才开单。伙伴一次只做一件。待询问优先于洗碗。
- [ ] 空闲时按顺序洗碗，洗完碗回到干净池。
- [ ] 用餐结束离席。等待超时离席并把仍开放的订单记为未满足。
- [ ] 只有营业和收尾都走完、且无人在座，才允许成功。未满足不导致失败。
- [ ] 成功收口把进行中的询问和洗碗按完成处理。
- [ ] 两个既有门禁实跑通过：`cooking-kitchen-loop`、`cooking-et-level-runtime`。
