## R1 · Derivation and provenance

Each invocation has a UUID runId; each gate/step, including repeated nested gates, has a distinct UUID resultId. One exclusive run root contains resultId subdirectories. Gate config is authoritative for ordered children, requirement flags and token declarations; JSON alone cannot change these. Synthetic examples contain the entire ordered tree, raw logs/TRX, raw optional producer receipt and a build/restore manifest with actual synthetic byte hashes. Every node is example=true, rejected in production before acceptance. Synthetic tool versions/timestamps/commands describe an illustration, not actual executions.

For each node let R=required, O=optional, C=completed, disjoint R/O with unique tokens. C is a subset of R union O. missingRequired=R−C; missingOptional=O−C. Gate C equals the union of validated direct child C intersected with its declared R union O; no independent parent assertion. bindings maps every C token to one or more descendant leaf resultIds that actually provide it. Its keys equal C; a reference must resolve in this tree, be Passed, declare/provide that token, and have valid evidence. Duplicate coverage is set union, never duplicate test counts. Distinct project/filter/configuration/TFM/host/policy define distinct tokens; do not grant an unfiltered suite from a focused test. Gate tokens must be mapped by config to child tokens, never inferred by name. Missing config mapping is Failed.

Passed means all declared required coverage is complete with valid evidence and no actual failed descendants. Failed/1 takes precedence over required Blocked/2, then incomplete required NotRun/4. Optional environment absence converts only validated Blocked reason MissingUnityInstallation to Skipped/3 on a config-approved edge. Preserve the full producer result in originalResult, including its own required mirror coverage, timestamps, command, raw processExitCode=2 and cliExitCode=2; effective edge has cliExitCode=3, processExitCode=2 and a policy reason. originalResult is evidence, not another executed child. Any other optional Blocked (missing provenance, binary or tool not explicitly permitted) propagates Blocked; any failure, invalid receipt or mismatch propagates Failed. All-optional/all-unexecuted trees without completed coverage are Skipped/3, including unselected optional leaves. Empty declarations/configurations are invalid, not vacuous Passed.

Provenance manifest records example flag, producer IDs, source SHA/dirty, config hash, project/configuration/TFM/SDK, exact stage commands/exits and four distinct sets:

1. immutableInputs: source, project/import/reference declarations, generator identity, NuGet/config and declared lock inputs. source.inputManifestSha256 / inputManifestAfterSha256 fingerprint only these immutable inputs, stable before/after restore, build and reuse. Generated project.assets.json and binaries never belong to this invariant source set. Fingerprints use SHA256 of sorted UTF-8 logical path + NUL + content SHA256 + LF records; every entry has a hashed artifact binding. Lock absence is explicit, never a claim of locked restore. If restoring intentionally creates a lock, record it as a generated restore output in a separately declared scope, not as an unchanged source input; the current specimen remains lockFile=Absent.
2. restore.inputs: the restore-relevant subset of immutable inputs (projects/imports/package declarations/config/declared lock), with inputBeforeSha256=inputAfterSha256 for these inputs. restore.assetsBefore is nullable when no prior assets exist; restore.assetsAfter is the generated output bound to restore producer IDs. Creating assets or changing their bytes is normal fresh restore behavior, not a source mutation. Archive the prior snapshot separately rather than overwriting it. All generated assets in the transitive restore closure follow this rule; the specimen uses one representative project.assets.json.
3. build.inputs: captured AFTER valid restore finishes, immutable build inputs plus the exact generated restore outputs used by this build. build.inputBeforeSha256=inputAfterSha256 applies across build only, excluding generated binaries; restore assets must remain unchanged through build. The synthetic manifest uses logical restore/project.assets.json with its actual restore-output artifact reference. build's producer IDs own the separate binaries output list; capture DLL/deps/runtimeconfig and generator identity in real implementation. A build that implicitly restores must create a distinct nested restore scope and capture build inputs after it, not compare generated assets to a pre-restore source fingerprint.
4. reuse: consumerInputBeforeSha256/After cover immutable inputs and equal the prior valid immutable source fingerprint. consumerAssetsBeforeSha256/After equal restore.assetsAfter's hash; consumerBuildInputBeforeSha256/After equal the producer build input fingerprint; consumerBinariesBefore/After equal the producer output manifest and current disk bytes. Stage outputs are verified under explicitly allowed roots, with producer IDs, source/config/SDK/project/configuration/TFM and actual bytes matching. For a multi-project closure these checks apply to the complete named asset/output sets, not one hash standing in for all outputs. Changes to immutable source/config at any stage fail, as do stale restored assets, mismatched build inputs or overwritten binaries. Restore must finish before build input capture, and build before consumer invocation.

A consuming result references the hashed manifest and records noBuild/noRestore. Build/restore evidence may come from an earlier run only through an explicitly allowed build root, never as current test evidence. Clean SHA alone is insufficient; dirty reuse needs identical immutable and stage input fingerprints. Missing manifest is Blocked; present corrupt/mismatched manifest is Failed. NoRestore/NoBuild records those operations NotRun at the consumer and relies on validated prior assets/binaries; it never credits a current restore/build. A separate upstream restore/build in the same invocation keeps its actual own coverage. Historical manifests cannot be fabricated from later outputs. Hashes prove byte identity, not power-loss durability or trusted attestation.

## R2 · Invocation time versus process time

startedAt/endedAt describe the invoked gate/adapter scope; executionStartedAt/executionEndedAt describe the actual process, nullable when probing prevented launch. All non-null values are UTC RFC3339 Z and ordered; child invocation falls within parent invocation and process times within its node invocation. Unselected/aborted/not-started leaf NotRun has all four times, command and processExitCode null; its planned command is carried by config, not reported as executed. A focused gate was invoked: retain actual invocation timestamps/command and executed subtree even when aggregate NotRun means full gate was not accepted. Aggregate has no process timestamps or processExitCode (runner's derived exit is cliExitCode). Blocked tool probe may have invocation times and attempted command but no process times/exit. Native legacy business exits are recorded separately and interpreted by kind, not by numeric status lookup.

Examples explicitly include focus-success+unselected leaf (aggregate NotRun/4), focus-failure+unselected (Failed/1), required Unity blocked+unselected (Blocked/2), optional missing Unity+successful .NET evidence (Passed/0), and missing child receipt normalized as Failed with observed exit0. fullGateAccepted is true iff resultType=gate and derived status=Passed. Passed leaf always has false. Aggregate tests are null; consumers compute totals once over unique test-bearing leaf resultIds. Never count originalResult or gate totals twice.

## R3 · Paths and ownership

Serialization accepts slash-only relative path segments `[A-Za-z0-9_-][A-Za-z0-9._-]*`. Thus it rejects backslashes/mixed separators, rooted/UNC/drive paths, colons/ADS, empty segments, dot/dotdot segments, trailing dots, reserved Windows device names (case insensitive CON/PRN/AUX/NUL/COM1–9/LPT1–9, including extensions) and traversal. Schema rejects slash/backslash/traversal/colon forms; semantic validator additionally checks trailing dot/device names. This conservative grammar is for generated evidence names, not arbitrary user source filenames; input entries use escaped IDs if needed with private path mapping.

Artifact root is explicitly run-step or build. For run-step, producerRunId=current runId and producerResultId=own resultId and path resolves beneath precisely that node's run/result root. originalResult belongs to the same physical node but is preserved as a hashed producer receipt. For build, allowed root is chosen by the invocation context/manifest, not by report data; verify producer IDs/hash/manifest before reuse. Resolve filesystem roots and every existing component; reject any symlink/reparse component (including a linked allowed root) rather than guess Windows junction targets. Compare canonical path components under platform case rules with a directory boundary, never string StartsWith. Missing/non-file, old-run root, sibling directory, link/junction escape, hash/size change are rejected. Tests use a temporary owned root; simulated reparse observations test policy on hosts without link privilege, while real symlink/junction tests are separately Blocked if creation is unavailable. No fixture deletes or alters external targets. Exclusive create and pre/post source/binary hashes catch reuse/concurrent writes; same-name nested gates use IDs, not display names.

## R5 · Counts

tests=null means N/A (build/audit/measurement), not zero tests. Test leaf stores declared=true and total, resultEntries, executed, passed, failed, skipped, notExecuted. Leaf NotRun tests=null with reason and declared test coverage uncompleted; console says tests NotRun. For a test report: total=resultEntries=passed+failed+skipped+notExecuted; normalized executed=passed+failed. Skipped/ignored cases did not execute; skipped and notExecuted remain separate nonexecuted categories, never added to executed. IDs must be unique executionId / NUnit case id (data rows count individually; parent suite records do not count). Passed test leaf requires total>0, executed>0, failed=skipped=notExecuted=0 for required test token completion. The nonzero skip specimen has total=3, passed=1, skipped=2, failed=notExecuted=0 and executed=1; its required coverage is incomplete and effective result Failed/1 despite process exit0. An explicitly excluded suite needs a distinct config token/policy, not a silent exemption.

TRX terminal entries: Passed→passed; Failed/Error/Timeout/Aborted→failed; Inconclusive/Warning→failed conservatively; Completed is rejected unless a producer-specific contract establishes its meaning; NotExecuted/Pending/NotRunnable/Disconnected→notExecuted. Unknown outcomes fail parsing. No canonical TRX skipped outcome: ignored/skipped framework records emitted as NotExecuted count there, not executed. Reconcile TRX total/actual executed and each native outcome counter against unique terminal entries before combining failure or nonexecution groups; e.g. normalized failed includes raw failed+error+timeout+aborted+inconclusive+warning, and normalized notExecuted includes corresponding raw nonexecution categories. A raw counter naming a different producer-specific statistic must retain its original meaning and be explicitly mapped or rejected, never be relabeled actual execution.

Unity NUnit Passed→passed, Failed→failed, Skipped/Ignored/Explicit→skipped, Inconclusive→failed; labels Ignored/Explicit on Skipped remain skipped. Reconcile native total/testcasecount, passed, failed, inconclusive and skipped separately: native failed excludes inconclusive, normalized failed includes it. Native ignored, when present, is a subset of skipped, not an extra total category. Standard NUnit root need not contain an executed field; derive normalized executed from reconciled passed+failed groups. If a producer supplies executed, verify its documented meaning against outcomes and never count skipped as actual execution. Raw result/report diagnostics remain unchanged; counter contradictions fail validation. Expected negative assertion counts belong to the harness assertion suite, not failed business commands counted as passed tests.

Schema stores all six counters plus resultEntries; executed is redundant but checked by equality. Production helper is the single semantic validator, with format-specific adapters sharing it; console/summary/exit use its normalized tree only. Planning validator checks its explicitly declared schema keyword subset plus tree semantics and synthetic artifact bytes; it does not prove production XML/report adapters or runner branches work.
