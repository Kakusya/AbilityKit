### Supported public facade

- Constructor(client:28-33) accepts participant, credential, Func<ITransport> factory and CookingNetworkSessionOptions. Default existing reliable LiteNet v3 stays unchanged. Factory is sufficient to inject existing InProcess endpoint or an application-only forwarding/observation transport; no new client constructor/framework abstraction is necessary.
- ConnectAsync(client:35-47) installs existing framed ConnectionManager, disables automatic reconnect, sends Join on Connected and waits actual exact-identity Ready. Hard built-in timeout is 15 seconds with cancellation. Start task without awaiting it on the same thread that must drive Host.ProcessOwnerFrame; pump existing owner normally until task completion, then await. Connect completion alone is not proof of every subsequent newest baseline grant.
- ReconnectAsync(client:49-52) disposes connection, resets client sequence, creates fresh transport, sends retained ServerSessionInstance/RebindToken. Same facade must survive reconnect: constructing a new facade loses private rebind binding. Calling ConnectAsync repeatedly without Disconnect is not the supported seam; reconnect explicitly uses ReconnectAsync.
- LatestBaseline/IsSynchronized/ServerSessionInstance/RebindToken(client:24-27) are public. ConnectionGeneration is accessible from LatestBaseline.Identity, not public Joined. There is no public ReadyIdentity, Connected, issued ACK ledger or baseline/terminal event.
- OnPacket(client:60-92) decodes, installs full baseline, sends exact ACK, recognizes Ready only if equal to LatestBaseline.Identity, completes correlation waiter or fails authority-unavailable/join. TryInstallBaseline(client:94-117) checks instance/generation/participant/schema/full scope consistency/hash/ordered participant metadata/current owner binding and monotonic snapshot/epoch; freezes complete State and Session. This central validation should replace duplicated gameplay client validators rather than relaxing it.
- SendCommandAsync(client:129-142) requires IsSynchronized/binding/baseline, allocates bounded pending waiter, freezes command and uses current scope, generated correlation and increasing sequence. Caller supplies stable ID; preserve it over rebind retry. AwaitResponse(client:144-148) is 15 seconds, independent of driver30-second guards. Do not turn timeout into success or increase it for migration.
- Disconnect/Dispose(client:149-156) mark unsynchronized, fail outstanding waiters and dispose underlying connection. This cancels caller ownership, not logical domain execution or durable receipts.

### What specialized drivers add, and what cannot be replaced blindly

RichPeer duplicates Join/framed connection/decode/baseline hash/ACK/Ready/sequence/rebind(client-equivalent logic at RichPeer:48-169). RichRunner:195-220 separately waits terminal then recipe projection version >= actual terminal StateVersion; preserve both conditions after facade integration. Facade task completion is terminal receipt, not committed full projection or natural-close proof.

RichPeer also supplies genuine acceptance evidence: copied raw received bytes/hash, exact wire/correlation/sequence records, actual ACK and Ready identities/ordinals, bounded validated-image ledger, watched committed image, drop-once terminal and malformed-input alteration. Facade exposes none of these as public observer APIs. Replacing RichPeer by only LatestBaseline + IsSynchronized would LOSE current checkpoint proof (RichPeer.Checkpoint:172-177), lost-response proof (RichRunner:200-213), and final newest exact ACK/Ready proof (RichRunner:326-350). Do not equate IsSynchronized with exact newest Ready: same-scope baseline installation can retain synchronization while ACK/Ready for that new image is outstanding. No private reflection is permitted.

FramedFaultPeer:18-85 duplicates Join/current full-state validation/ACK/Ready/pending command completion and drop-one reply; migration would add facade's stricter validation and 15-second task deadline. Its custom correlations, caller task lifetime without built-in timeout, public-to-driver Binding and ReadyIdentity are not facade equivalents. Existing scenario proof must explicitly account for deadline change, not silently substitute production15 for old driver30 or preserve30 by changing client.

### Existing transport decorator seam and limits

Existing ITransport (Unity/Packages/com.abilitykit.network.runtime/Runtime/Network/Abstractions/ITransport.cs:5-18) exposes IsConnected, Connected/Disconnected/Error/BytesReceived, Connect/Close/Send/Dispose. A factory-created app-only decorator may forward those existing events/operations and retain immutable evidence of framed send/receive without touching gameplay authority. ConnectionManager emits complete PacketReceived/ServerPushReceived at Runtime/ConnectionManager.cs:417-453, but facade owns it privately: ITransport operates BELOW those complete-packet events. A raw BytesReceived callback must NOT be presumed a complete wire envelope.

For exact complete-envelope observation/drop, decorator needs an independent bounded framing accumulator/decoder consistent with the existing codec, handling fragmented/coalesced receives. Forward unchanged bytes normally; suppress exactly the selected complete terminal frame only; preserve all other frames/order and byte ownership. This is test-driver glue, not a new protocol, UDP loss claim or authority. It must observe outgoing Join/ACK/Command and incoming Joined/Baseline/Ready/Result to retain actual identities/ordinal/hash evidence. Correlation is facade-generated cmd-N: select drop by observing stable command ID on the outbound command and mapping its actual correlation; never guess/rewrite correlation. A dropped original facade waiter must remain unresolved until disconnect/15-second timeout; record it explicitly and observe eventual exception, then retry same stable ID after actual rebind and prove cached outcome/one settlement/full graph unchanged.

No complete-frame decorator currently found in these three source files. Therefore FULL rich replacement is conditional on reviewed bounded app-only proof glue and controls, not immediately accomplished by swapping type names. Keep specialized raw peer for intentional invalid generation/scope/sequence/ACK/payload controls, which public facade deliberately cannot send. Those controls test framework rejection, not normal gameplay networking.
