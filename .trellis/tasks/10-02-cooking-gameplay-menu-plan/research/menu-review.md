### 72 供应 / 60 半成品 / 19 工位的实际映射

保留 worktree `S04/research/source-audit.json` 记载 87 菜品、367 原始加工节点、60 半成品、72 供应、19 工位、7 来源。该审计有 **31 条差异**，全部为 D01–D31 的 computedStationClosure：原 Excel 菜品工位集合缺贴单台，扩展集合增加贴单台。解决规则：保留原单元格与差异；区分制作依赖和交付依赖，饮品交付闭包加入贴单能力，不把贴单伪装为配方加工节点。不得改原附件消除差异。

保留目录实际是 282 材料 = 72 Supply + 60 Preparation + 87 Finished + 63 Stage，210 recipe steps、19 station records、27 实际引用容器类型、87 menu entries。210 不等于原始367节点丢失147节点：原节点含重复共享准备/人工汇总；必须给每个原节点明确“共享映射、展开映射、交付操作或非独立操作”理由，不能仅比较总数。

生成器目前用表行顺序 zip 静态 slug 列表：调换两行仍可能得到数量正确但身份错误的配置。改为源编号→稳定 ID 的明确表，并校验编号、名称与定位；生成确定性不能依赖 XLSX 排序。Supply/Preparation 名称字典覆盖也须拒绝同名冲突，允许别名必须显式声明。

19 工位是功能目录，不是19独占全局实例。蒸汽机保留 heat-milk 与 foam-milk 两模式、同一物理工位占用；搅拌/搅打/榨汁、煎/炸/蒸/烤/架烤保持不同能力。清水/热水、可乐液/接取可乐、苏打液/接取苏打须通过原始 P 编号映射，不能新增无来源供货偷跳步骤。供应番茄酱与现制番茄热酱、速溶奶茶与现泡奶茶必须不同 DefinitionId；D28 无茶，椰果/仙草供货，熟珍珠需要煮。

### S04 可执行契约

每条来源固定 SourceId、SourceLocator、SourceSha256、中文名、稳定 DefinitionId；配方输入为正整数份数 multiset。向旧 DTO 投影可展开重复项，但核心验证、匹配、消耗、容量、canonical、checkpoint 必须保留计数；DefaultInputs 不能变成免费提供第二份牛奶。未知、零、负、溢出计数拒绝且零变更。

拓扑每个非供应状态必须有明确 producer；共享准备复用同一 ID。图环、悬空、最终输出与模板错配、不可达材料/设备/容器拒绝。多种合法 producer 若确有产品需求应显式允许，否则保持单 producer，不能生成器猜选。选择菜单只取完整依赖闭包，关卡允许范围与已解锁取交集；实际实例数量、工位可达性及补料通路由 S07/S08/S14 联合检查，不由能力字符串存在代替。

独立备料分支可以任意合法顺序推进；阶段依赖用明确中间物件表达，不能仅 MustLast 布尔或排序索引。D31 茶→加冰→奶盖，D18 奶泡最后，D20 奶油最后，D02/D03 苏打最后，D19 冰/椰奶后浓缩。阶段不能通过直接构造最终产品、跳阶段配方或订单配方误认绕过。拿出中间物可暂存交接，状态不变。测试必须实际提交错误早加料，不只修改静态图。

加工 carrier 和出餐 vessel 明确分离；工作容器可转移内容而非交顾客。按份盛装走 S03 的同一份数权威；旧 Pour 不暗改为单份。取一份产出单一物件、原容器剩余减一，耗尽后可复用。当前生成器依 capability 选择通用 carrier，未必保留倒模/脱模的真实 container 关系（S04–S06 cake）；必须单独记录 CakeMold 的装入/烤制/脱模及烤盘/蒸篮/炸篮如何卸载，避免将源文模具步骤仅写进 Operation 字符串。

成本、加工 Tick、产量、初始供货与评分暂用显式 fixture；保留目录 RequiredTicks=1、部分准备 YieldPortions=2、材料8份、出餐容器2、BaseScore=100 是测试值，不能覆盖旧汤/吐司或宣称正式平衡。需检查一次批量足以满足×2饮品且重复生产可恢复供应；不能因初始8份够一次测试就宣称营业供应闭合。

### S05 可执行订单绑定契约

绑定属于现有 Recipe/Order owner，成品身份独立且制作无需 OrderId。对出餐容器/其中唯一最终成品建立稳定绑定，checkpoint 明确同一对象；不是副本票据背包。命令 BindOrder/UnbindOrder/RebindOrder 均具 scope/player/command identity、距离和目标版本；同一 Tick 两人绑定同一杯仅一成功。绑定必须检查可交付成品、合法杯型、当前未完成同 scope 订单和配方匹配。解绑保留内容；换绑原子校验新单后切换，失败旧绑定保留。

默认每成品最多一绑定，每订单最多一有效待交付成品，防重复劳动；若不匹配直接拒绝，别自动改配方。订单关闭/换代清除失效绑定，不能将旧单带入新 Level；同 Level checkpoint 保留绑定/去重/版本并恢复相同后续行为。饮品 RequireBinding 策略必须进入真实订单配置、validated identity 与提交检查。当前菜单 RequiresBinding 只在目录校验与所需能力使用，投影 OrderTemplate 没绑定字段，runtime SubmitOrder 没绑定校验，这是交付阻断缺口。

餐食和甜品允许未绑定直接核单提交，不增加贴票动作。31饮品无绑定提交拒绝、绑定错单拒绝；加工容器与非成品拒绝，提交成功只结算一次。成功消费成品后撤销绑定并按既有容器净/脏/消耗策略回收；不对所有热杯/透明杯假定可洗永久循环，须配置可洗与消耗类型并纳入供应闭包。完成订单后的历史记录用于结算，不能继续作为可绑定目标。

## Caveats / Not Found

1. 保留 worktree 是停止的未合并工作；本研究没有重启、运行测试或认可其历史 focused-test 日志。
2. 主分支 ×2 匹配与验证缺口是真实阻断；目录 RequiresBinding 传播缺失是真实阻断；运行适配必须公开映射 Manual/YieldPortions 并校验其值，现有 adapter 检查未覆盖这两个新字段。
3. 图静态闭合不证明工位容量/角色距离/营业补给/容器回收闭合；S07/S08/S14 必须联合验收。
4. 生成器从源码次序配 slug、倒模步骤与carrier关系，以及原367节点对210配方的逐节点来源映射仍需补齐；任何 source comment 或文字Operation 都不是可执行规则。
5. 最新任务头与旧正文授权文字存在历史冲突；本研究仅提供审议结论，由主会话统一记录当前owner授权，不修改scope或启动任务。
