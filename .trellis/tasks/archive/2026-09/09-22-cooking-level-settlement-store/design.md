# 已确认小关结算落盘：技术设计

需求见 [prd.md](prd.md)。本设计只把已经确认的代际列表写成文件。不调用 `CookingProgressPersistence.Apply`，不改长期进度，不选平台存档目录。

## 决定

新增一个文件记录器，消费现有的 `CookingLevelSettlementConfirmation`。它不替代内存账本 `CookingLevelSettlementLedger`。

内存账本继续负责「这一进程里，这一代确认过没有」。文件记录器负责「这一目录里，这一代的列表还在不在」。两者的重复和冲突规则相同：同一列表是重复，不同列表拒绝且不覆盖。

不把列表塞进 `CookingLongTermProgress`。那条进度必须带奖励，`Apply` 会改货币。也不把列表塞进 `CookingLevelCheckpoint`。checkpoint 是运行中的厨房，成功交接会把结算账清掉。

## 边界

| 层 | 责任 | 不负责 |
|---|---|---|
| `CookingLevelSettlementLedger` | 进程内按代际去重 | 写文件 |
| 文件记录器 | 把一份确认写到调用方给的目录，并按身份读回 | 判断关卡能不能结束，计算奖励 |
| `CookingLevelEtHost` | 仍只在 `Ended` + `Success` 且未交接时取出 `SettlementHistory`；调用方再交给文件记录器 | 选择存档目录，自动进入下一关 |

宿主不直接碰 `FileStream`。测试或以后的应用层持有目录根，把确认结果交给记录器。这样领域类型里不会出现路径。

## 数据流

```text
Ended + Success，尚未交接
  -> 宿主 ConfirmSettlements(内存账本)
  -> 内存确认为 Confirmed 或 Duplicate
  -> 同一份确认交给文件记录器
       目录里没有这一代：写入
       已有同一列表：重复，不重写
       已有不同列表：拒绝，不覆盖
  -> 调用方之后自行 CreateSuccessor

新进程
  -> 同一目录根上的新记录器按 Match + LevelId + LevelEpoch 读取
  -> 读到的列表与写入前一致
```

内存确认失败时不写文件。文件写入失败时，这一次内存确认也要撤回，避免「内存说确认了、磁盘没有」。同一进程里的其他代际不动。

## 文件契约

- 一个代际一个记录。文件名由 Match、`LevelId`、`LevelEpoch` 派生，不使用调用方传入的原始字符串当路径片段，避免目录穿越。
- 记录内容是格式版本、身份、结算列表和完整性校验。列表字段保持 `CookingOrderSettlement` 已有的八项，不增加评分或金额。
- 写入先落到同目录的临时文件，完成后再替换成正式记录。替换前的读取只看正式记录。
- 正式记录被截断或校验失败时，读取返回结构化错误。不回退成空列表，不删除坏文件。隔离和修复不在本任务。
- 不实现格式迁移。未知版本直接拒绝。

## 不采用的做法

- 复用 `InMemoryCookingProgressStore` 再加一个文件实现去记奖励。奖励对象还没有合法的零值语义。
- 把整本内存字典一次写成一个大文件。一条坏代际不应让其他代际的读取协议变成「整本不可用」以外的隐式修复。本任务按代际分记录，读取也按代际。
- 在 `CreateSuccessor` 里自动落盘。确认失败和交接仍是调用方的两步。

## 风险

- 测试里的「新进程」只是新对象。它证明目录内容足够重建这条确认，不证明操作系统在断电半途的替换语义。这个差距写在验收外，不写成已验证的崩溃恢复。
- 若文件写入失败后内存账本已经记下这一代，重试会被当成重复并且不再写盘。所以失败必须撤回这一次内存登记。
- 目录根由测试传入系统临时目录。不要把仓库路径或玩家目录写进记录。
