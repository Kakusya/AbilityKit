# Cooking 可见顾客与固定伙伴运行时纵切

更新：2026-09-28。状态：implemented / verified。

## Goal

在不改变既有前厅节奏和单机纯 C# 边界的前提下，把当前隐藏在 `CookingFrontOfHouse` 内部的桌位、顾客和固定伙伴工作状态升级为稳定、可观察、可恢复的权威运行态，使未来表现层能够按稳定身份投影顾客与伙伴，并使同一 Level 的 checkpoint 恢复与不中断运行保持确定性一致。

## Background

- Owner 已确认采用“可见顾客 + 自动服务 + 餐桌控制客流”的半抽象顾客方向；玩家继续专注做菜，不承担逐桌带位、点单、送餐、结账或清洁微操。
- Owner 已确认 NPC 是少量、具稳定身份、长期陪伴餐厅的固定伙伴，不是可不断招聘替换的普通员工。
- 当前 `CookingFrontOfHouse` 已实现到店、占桌、询问后开单、伙伴空闲洗碗、用餐占桌、超时未满足、营业/收尾和跨关清理，但桌位、顾客与伙伴工作只是内部可变对象，只向外暴露聚合计数。
- 当前订单 ID 由桌号派生；同一桌接待第二批顾客时会复用订单身份，无法形成可靠的多批顾客纵切。
- 当前 `CookingLevelCheckpoint` 只恢复厨房与宿主水位；附加的前厅运行态不会随同一 Level 的宿主销毁/重建恢复。

## Requirements

### R1：稳定顾客身份

- 每次成功入座创建新的 Level-local 顾客身份，身份在该顾客从入座到离席期间保持不变。
- 同一餐桌连续接待多批顾客时，各批顾客及其订单身份必须不同，且身份分配只由权威固定 Tick 顺序决定。
- 顾客离席后身份不得复用；跨 Level 重置后允许从新的 Level-local 水位重新开始。

### R2：可观察顾客状态

- 对外提供不可变前厅快照，至少包含顾客身份、餐桌身份、到店顺序、当前阶段、阶段内计时和关联订单身份。
- 顾客阶段覆盖等待询问、询问中、已开单等待出餐、用餐；离席通过后续快照中该身份消失表示。
- 快照必须按稳定顺序输出，调用方不得获得内部可变集合或对象引用。

### R3：可观察固定伙伴状态

- 前厅拥有一个稳定伙伴身份。
- 快照至少包含伙伴当前工作类型、目标顾客/餐桌或脏碗、已用 Tick 和所需 Tick。
- 伙伴仍按既有规则优先处理到店顺序最早的询问，无待询问顾客时按脏碗队列处理清洗；本任务不增加玩家指派或优先级微操。

### R4：权威节奏兼容

- 现有到店、询问、开单、洗碗、超时、用餐、营业结束和自然成功语义保持不变。
- 暂停不推进前厅；成功收口继续把进行中的询问和洗碗按完成处理；失败重开和下一 Level 继续使用既有清理边界。
- 顾客可见化不得创建第二套订单、计时或成功判定状态源。

### R5：快照规范化与哈希

- 前厅快照提供确定性的 canonical 文本和 SHA-256。
- 相同输入与 Tick 序列必须产生相同快照和哈希；任何顾客阶段、伙伴工作、队列或时钟差异都必须改变 canonical/hash。
- 快照只描述当前权威状态，不保存表现动画、寻路、坐标或历史事件流。

### R6：同 Level 恢复 checkpoint

- 新增自包含的前厅 checkpoint，覆盖日程配置、活动顾客/桌位、伙伴工作、洗碗队列、未满足记录、营业时钟和身份分配水位。
- `CookingLevelCheckpoint` 在启用前厅时必须携带该 checkpoint；未启用前厅时保持可选为空。
- 恢复必须先完整校验再替换状态；失败不得留下半恢复前厅。
- checkpoint 格式版本升级且不提供旧版本迁移；旧版本以结构化版本错误拒绝。
- “运行中导出 → 销毁宿主 → 重建 → 继续”必须与不中断基线在厨房、前厅、宿主帧序号和最终 canonical/hash 上一致。

### R7：范围约束

- 保持纯 C#/.NET，不实施 Cooking Unity package、场景、UI、动画、寻路或 EditMode。
- 不修改 LAN wire 协议，不做两台物理机 LAN、KCP、主机迁移或跨设备恢复。
- 不实现伙伴成长、岗位切换、长期关系、顾客分组、开桌/闭桌、波次预告、收益、小费、评价或新的评分公式。
- 不改变 `09-19-cooking-productization-network-slice-planning` 的 `planning_only` 产品事实来源定位。

## Acceptance Criteria

- [x] AC1：单桌至少连续接待两批顾客；两批顾客和订单身份均不同，第二批订单能够正常开单、完成或超时，不受第一批记录冲突影响。
- [x] AC2：等待询问、询问中、已开单、用餐四个阶段均可从不可变快照中观察，字段与权威内部状态一致且顺序稳定。
- [x] AC3：伙伴询问与洗碗期间的身份、工作类型、目标、已用/所需 Tick 可观察；空闲时无残留目标。
- [x] AC4：两次相同运行的前厅 canonical 和 SHA-256 相等；改变任一顾客阶段或伙伴工作进度后哈希不同。
- [x] AC5：在询问中、洗碗中和用餐中至少各覆盖一次 checkpoint round-trip；恢复后继续运行与不中断基线终态不可区分。
- [x] AC6：非法或投毒的顾客身份、桌位占用、订单关联、伙伴目标、队列重复项或时钟水位被结构化拒绝，原对象零变更。
- [x] AC7：失败重开清空顾客与伙伴工作；下一 Level 清空前厅但保留既有厨房脏碗语义；成功收口继续完成进行中的询问/洗碗。
- [x] AC8：既有 Cooking 前厅、厨房闭环、ET Level runtime 和跨关 LAN 测试无回归；权威门禁实际通过并写入 `check.jsonl`。

## Key Decisions

- 本任务是“运行态可观察性与恢复合同”纵切，不是表现层纵切。
- 顾客身份是 Level-local 单调身份；订单身份跟随顾客，不再跟随餐桌复用。
- 固定伙伴只落稳定身份和当前工作状态；名字内容、成长与岗位系统后置。
- 前厅 checkpoint 只服务同一 Level 的宿主恢复；成功跨关仍按现有规则清空前厅。

## Deferred Items

- 伙伴名字/内容目录、伙伴成长和长期关系。
- 顾客类型、团体桌、客流波次、开桌/闭桌和空间寻路。
- 收益、小费、评价及其与既有积分/星级的关系。
- Unity 可视化、动画和交互。
- 网络协议投影与两台物理机验收。
