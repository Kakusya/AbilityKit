# 独立审计与修复记录（2026-09-21）

> 本文件记录交付后的独立审计结论、针对审计发现所做的修复，以及可复现的独立验证方式。
> 它不改变 `prd.md` / `design.md` 已批准的契约内容。

## 1. 审计方式

owner 要求"开启子智能体审计测试方法，并有切实、独立、明确的证据"。因此做了两件互相独立的事：

1. **子智能体审计**（`general-purpose` agent，只读 + 可跑测试，禁止修改/暂存/提交）：按 A 覆盖性 / B 空洞测试风险 / C 变异检验 / D 证据真实性 / E 规范与实现一致性五个维度逐条审，并要求对 3 个关键实现点实际做变异（破坏 → 跑测试 → 还原）。
2. **独立复核脚本**：`artifacts/cooking-kitchen-loop-contracts/independent-verify.py`。它**不调用被测 C# 代码**：
   - SHA-256 由 python `hashlib` 重算 golden canonical bytes；
   - 测试计数与执行时长由解析 TRX 得到（不信 `dotnet test` 的汇总行）；
   - golden 向量按 `CanonicalWriter` 的帧格式（大端 int32/int64、长度前缀字符串、可空标记字节）手工解码，逐字段比对 evidence 记录。

## 3. 审计要求复核的两处"证明力"说明

- **既有 golden 向量未变**：审计用 `git show HEAD:src/AbilityKit.ET.Runtime.Tests/CookingLevelEtHostTests.cs` 取回改动前的断言，与当前 hex/SHA-256 常量逐字符比对，确认 diff 只增加了 evidence 追加代码。独立复核另外用 `hashlib` 对 evidence 里的 canonical bytes 重算 SHA-256，与测试断言常量一致。
- **新 golden 向量是真实输出**：该向量由先写占位断言、跑测试取回真实输出、再锚定的方式生成；审计与独立复核都用 python 独立重算确认。期间另做一次变异（从 `CanonicalBytes` 删掉 `command.Process` 字段），三条指纹测试全部失败，证明金样与跨表面断言都有杀伤力；变异后文件已还原，`git diff` 为空。

## 5. 复现方式

```bash
# 1. 跑 gate 并让测试把证据写进 artifacts（5 个 evidence 目录环境变量）
COOKING_CONFIGURATION_EVIDENCE_DIRECTORY=$PWD/artifacts/cooking-kitchen-loop-contracts/configuration \
COOKING_RECIPE_EVIDENCE_DIRECTORY=$PWD/artifacts/cooking-kitchen-loop-contracts/recipe \
COOKING_RECIPE_MATCH_EVIDENCE_DIRECTORY=$PWD/artifacts/cooking-kitchen-loop-contracts/recipe-match \
COOKING_MATCH_LIFECYCLE_EVIDENCE_DIRECTORY=$PWD/artifacts/cooking-kitchen-loop-contracts/match-lifecycle \
COOKING_FINGERPRINT_EVIDENCE_DIRECTORY=$PWD/artifacts/cooking-kitchen-loop-contracts/fingerprint \
powershell -ExecutionPolicy Bypass -File tools/run_test_gate.ps1 -Gate cooking-et-level-runtime

# 2. 把该次 gate 输出复制进 artifacts/<...>/（gate-summary.json、*.log、test-results/*.trx）

# 3. 独立复核（不调用被测 C# 代码）
python artifacts/cooking-kitchen-loop-contracts/independent-verify.py
```

注意：每次跑 gate 都会生成新的 GUID 证据子目录，因此第 3 步之前需要先用
`python local/verify/realign.py` 把 `check.jsonl` 与 `implement.md` 的路径/数字对齐到本次运行。
