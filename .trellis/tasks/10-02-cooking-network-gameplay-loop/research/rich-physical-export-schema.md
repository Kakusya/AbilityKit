# Rich physical companion export schema v1 and source map

2026-10-03 DOC ONLY, required before new runner/verifier implementation approval. DTO names below are proposed new application-owned records, not production/wire schema changes. Typed captures reuse current supported public Cooking DTOs; Level format current/Recipe5/protocol3 checked, no silent field defaults. Both endpoint reports use same rich-report-v1 schema and cutpoint/run ID. Side-by-side caller checkpoint is evidence, never restored as authority.

## Top-level RichPairEndpointReport

Required fields: SchemaVersion=1, Suite=rich-recovery-four-cutpoints-v1, Role(host/client), RunId, CaseId(manual-paused|automatic-active|unbound-cup|submitted-reply-lost), Passed, Failure(stage/message/exception nullable), Stage, LocalProcessReceipt(Pid,StartUtc,ExitCode nullable until supervisor finalizes, executableSHA256), TopologyClaim, EffectiveEndpoint(bind/port orremote), Runtime/OS, ProtocolVersion, LevelFormatVersion, RecipeSchemaVersion, Provenance, RolePolicy, Budget, Phases[], Cut, Ended, Successor, Final, ObservedIngress[], ObservedReplies[], CallerCommands[], CallerOutcomes[], DroppedReply nullable. Required absent evidence fails coverage; report-only Passed cannot substitute original supervisor exit0 receipt.

Provenance: FullSourceHead, DirtyState, SavedPatchSHA256 nullable, BinaryManifest(relative name/SHA256 including deps/runtimeconfig/content and exact file set), RunnerScriptSHA256, linkedFixtureSourceSHA256, linkedPlannerSourceSHA256, ETMvid, SessionMvid, WireCodecMvid, OriginalMenuJsonSHA256, FixtureCatalogHash (RequiredTicks6 copy), ProjectedContentIdentity, FrontConfigIdentity, Layout/PreparationIdentity and RolePolicyHash. RolePolicy names Chef/Partner, who starts manual/continues/binds/delivers and fixed selected menus; no runtime content flag authorizes a different recipe.

Budget: WholeDeadlineMs600000, InitialJoinMs20000, OperationMs30000, CutRebindMs15000, ownerPumpDelayMs10, elapsed monotonic local counters, command/ownerFrame counts. Phases have unique ordinal/name, local start/end monotonic, marker stable/domain ID, full received/matched milestone and successful required invariant names. No cross-PC duration subtraction.

## Reused complete typed objects

RichCaptureEvidence: EvidenceId, LocalMonotonicTimestamp, HostFrameSequence, BusinessHash (public Hash), FullRecipeCanonicalSHA256, FullFrontCanonicalSHA256 nullable, **CookingNetworkAuthorityCapture Capture** unabridged (FullRecipe Items/Containers/Processes/Deduplication/Events/TickEvents/NextProduct/NextProcess/NextSettlement/ConsumedProducts/Removed records/Supply balances/deliveries/origins, FullFront customers/orders/tables/work/wash, InstalledLayout, config/preparation/major projection/checkpoint availability and scope). Canonical files alongside reports are hashed and named; JSON object ordering normalized only, semantic arrays preserved.

RichCallerCheckpoint: EvidenceId, Participant, CurrentBindingMetadata(instance/generation; token NEVER exported), ValidatedBaseline **CookingNetworkBaseline**, recomputedCombinedHash, ExactAckIdentity **CookingNetworkBaselineIdentity**, ActualReadyIdentity, ReceivedBaselineOrdinal, AckSentOrdinal, ReadyReceivedOrdinal, RelevantWireSequenceWatermarks, PendingOriginalStableIdentity nullable, LastTerminalCorrelation nullable. Export directly after actual owner Poll; it does not call restore, install authority or manufacture permission. Host pre/post capture and Chef/Partner caller checkpoints reference the same case/phase/boundary, even if recipient combined session hashes differ. Current generation/scope enforced; retain the validated image matching the actual Running Ready grant even if a newer issue awaits ACK.

ObservedIngress: bounded ordinal, PhysicalChannelId, endpoint, afterForward timestamp, correlation/kind, typed **CookingNetworkWireCommand** or exact ACK identity; omit Join credential/token. OwnerConsumption: beforeCaptureId, afterCaptureId, actual **CookingNetworkOwnerFrameResult**, batch/HostFrameSequence, observed correlation references. ObservedReply: channel/correlation, typed actual **CookingNetworkWireResult**, owned framed bytes SHA256, send timestamp. CallerCommands: identical actual sent wire with sendordinal. CallerOutcomes: actual received result, correlation/generation/receiveordinal and byteshash. Discarded result lives only DroppedReply diagnostic and never completes original application waiter.

## Cut object, tagged variants

Common RichCutEvidence: ActualInjectedExactlyOnce=true, LifecycleAtCut, OriginalParticipant/OriginalGeneration/RecoveredGeneration, SameInstance, OriginalProcessId nullable, OriginalItem/Container IDs nullable, PreCutCapture, CommittedCutCapture, CallerBefore, CallerAtCut, HoldBefore/HoldAfter captures, RealClose(channel/endpoint/eventordinal), CleanupFrame and CleanupCapture, RebindJoined metadata sans token, RebindCallerCheckpoint, RecoveryFrame[], RecoveryCapture and CompletionMilestone. Include same scoped identities, actual actor roles and exact legal domain operations. No invented captured dummy result.

Manual fields: RequiredExecutionKind=Manual, LifecycleAtCut=Running, OriginalWorker=Partner, TakeoverWorker=Chef, ProcessId/Anchor/Inputs, ElapsedAtPause, PauseControlResult/capture, two pausedOwnerCall captures proving no HostFrameSequence/canonical/progress change, CleanupPendingWhilePaused, ResumeControlResult, postResumeCleanupCapture with ActiveWorker=null/sameelapsed, actual Chef ContinueProcess wire/admission/outcome, process completion/result. Preparing shared handoff stored as Phase evidence only.

Automatic fields: requiredAutomatic=true, ActualStartWire/Disposition/ConsumedCapture, elapsed<RequiredTicks6, ActiveWorker=null, issued incomplete baseline, exact pre-Start ACK observation, ownerHoldFrames=0 with equal canonical/frame, actualremote close, resumed cleanup frame/tick events and process evolution/results. Ready on reconnect legitimately requires owner frames; completion during recovery is valid only with precise one-time inputs/product/allocator proof.

Unbound fields: actual completed D31 item/vessel FullRecipe records, BoundOrder=null, portion before/after quantities+NextProduct/target contents, close/rebind pure-container preservation, actual Chef take/bind/submit wire/outcomes and delivery receipt. Product identity is actual allocation, not guessed ordinal.

LostReply fields: OriginalSubmitWire/stable/domain/player/scope, original actual Host admission/disposition/real outbound Accepted reply, exactly1 dropped matching received CommandResult diagnostic(byteshash/correlation/outcome), application waiter still uncompleted, committedCompleteCallerCheckpoint with1settlement/ConsumedProducts/tombstones, realclose/rebind/currentgen checkpoint, **identical original domain payload/stable identity** retry with newcurrentsequence/correlation, actual cachedAccepted IsDuplicate/domain/Outcome/Reason/StateVersion, before/after whole settlements/ConsumedProducts/full Removed item arrays/allocator/dedup canonical comparisons. It is applicationreply loss, not rawpacketloss.

## Ended, successor and final

Ended: genuine full capture before successor,2settlements/2completedorders,1unmet,0stars, recipeCompleted, frontClosing, emptywash, allFree/noactivework; lifecycle completion control results and legal cleaning commands retained.

Successor: exact source/target scopes, real TryFinishService/CompleteEnd/CreateSuccessor results, durable store artifact relative paths/SHA256, actual ReadBaseline result+typed saved payload or hashed raw file, store/Level format metadata, narrowed carry policy reference, side-by-side ended recipe/front/supply/allocator and saved kitchen/front/preparation values, created full capture, both successor CallerCheckpoints. Do not require out-of-policy old-scope receipt carry; verify approved included/excluded fields explicitly, never prune live recovery history before successor.

Final: immutable pre-close **CookingNetworkSessionProjection** with bothConnected/Ready/noCleanup, Host newest local/remote issued identities, actualexact observed remote ACK/outbound Ready, Chef/Partner validated newest successor baselines, full businesshash/canonical equality, actual current channel live-at-freeze, Client report written/livehold5000ms and Host observed actualclose, supervisor paired actualexit0. Preserve post-close projection separately; it cannot stand in for pre-close readiness.
