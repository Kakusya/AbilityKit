## Cases and exact proof obligations

Each case records pre-state, both exact wire inputs (sanitized metadata), post-owner actual admissions/dispositions, each endpoint terminal result and final typed full state. Different participants' identical stable strings remain separate identities; same-participant retry must preserve original payload and use a new current sequence.

1. **Same item Pickup**: both empty-handed players target the same existing item and identical valid expected version in one held prefix. Both inputs genuinely map; exactly one domain Accepted and one domain rejection, not client backpressure. One original item remains, solely in winner hand; loser hand empty; version/change matches successful operation. Two participant-qualified receipts/results, no copy/no disappearance/no new allocator IDs. Verify retries are cached without additional mutation. Record actual domain rejection (version/location validation order can determine reason); do not hard-code an invented reason.
2. **Same slot Drop**: legally obtain two different items first; both hold valid original versions and Drop into one initially empty ordinary slot in the contested frame. Exactly one domain Accepted, one rejected. Slot points only to winner item; losing item remains in loser's hand with original version/content; both IDs still exist once. Validate station occupancy and every item location, not only winner outcome. Cached replay neither overwrites slot nor releases loser item.
3. **Independent legal work**: after legal recovery/clearance, both players Pickup different available items (or Drop into distinct empty slots) in same prefix. Both domain Accepted in one consume batch. Full state shows two independent changes and two retained receipts. No accidental serialized two-frame success counted as concurrency; assert actual batch/admissions.
4. **Incompatible input recovery**: legally hold definition B and use existing CookingRecipeOperation.PutIn operation against genuine container accepting only A. Require actual domain ContainerRejectsItem, held item/container contents, versions and allocator unchanged, while rejection receipt is retained. Canonical comparison excludes only documented clock and receipt metadata; preserve full images so exclusions can be independently checked. Then a legal recovery Drop and compatible operation succeeds; no reset or raw mutation clears the error.
5. **Stale scope/identity**: send valid-shaped command with old/different level epoch (actual Map rejects ScopeMismatch), then wrong instance/current connection generation (ServerInstanceMismatch), same stable ID with changed payload (CommandIdentityConflict), and non-increasing sequence (MalformedCommand). Separate cases so early guards cannot mask intended guard. Record exact current instance/generation/sequence and both invalid/next-valid inputs. Invalid high sequence must not consume permission for a later legal lower-but-still-current sequence when guard precedes validation. Same-stable conflict cannot overwrite original receipt. Full items/slots/allocator/tombstones stay unchanged; clocks/session terminal watermarks accounted separately. Old-scope denial is not a fabricated actual successor; rich companion independently exercises real successor.
6. **Live disconnect and recovery**: after a genuine committed remote command, preserve binding token privately, close actual remote transport, wait for owner-observed closure/retired ownership, reconnect with same instance/token to obtain strictly new generation. Exact complete baseline/ACK required before next legal command. Retry original stable/payload in current generation proves cached identity without reexecution; new legal independent operation succeeds. Inject an actual old-generation shaped command on current socket to demonstrate denial, not send through a closed socket and call that authority rejection. Keep original receipt, item/content, NextProduct and any tombstones unchanged by cached retry. If testing pre-consume close, label premapping cancellation separately; no claim it creates persisted CancelledNoExecution. No cold replacement host is needed here.

At every proof boundary compare full item records (identity/definition/version/location/content/state/binding), all hand and station-slot relations, process list if any, full dedup receipts, NextProduct allocator and removed-item/tombstone representation exported by current full checkpoint.
