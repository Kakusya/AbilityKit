# Design and review
Before: four PS launchers use Port=0; Flow server loopback listener hardcodes0. After: Windows host startup calls cooking-firewall.ps1 -Action GetPort, sole range/occupied-port authority. Resolve installed fixed-location script first (same user configuration across worktrees), repository tool fallback when not installed. Never duplicate range scanning in callers. Validate Passed/GetPort/integer port/config bounds/UDP/unreserved/no mutation response before process starts. No automatic bind retry; startup fails clearly and a fresh test run reselects. Tool query is not a lease or LAN/firewall proof.
PS shared thin helper owns CLI result validation, sidecar provenance and READY matching. Add sidecars to run directories; preserve report schemas and frozen manifests. Explicit Port logged separately; do not claim firewall coverage for explicit ports. BuildOnly/Client do not select.
Flow parent calls selector within existing startup budget before server launch, passes candidate through private child environment value; accepted role CLI and control DTO remain unchanged. Child strict parse selected value, validates READY bound endpoint. Cleanup includes selector cancellation/process ownership. Add provenance to network-resources sidecar only. No changes to five gameplay message families, owner tick, ET runtime, package dependencies, flow result/event schemas or retry semantics.
Per-file consumers: tools/cooking-test-ports.ps1 and tests serve four active Cooking process wrappers; those four files consume helper only at host launch/READY. FlowAcceptance helper + NetworkFlowAdapter + NetworkRoleHost serve existing network fixed-flow test product; ET.Runtime.Tests Cooking test file(s) cover selector negatives/real network behavior. AGENTS and cooking spec document installed tool requirement and scope. Task manifests/evidence maintain review record. No other examples or Unity files.
Existing specialized impairment harness intentionally uses relay/driver allocations and frozen evidence; not migrated in this task. Existing in-process UDP transport unit fixtures use port0 to test binding itself and are not network host launch framework.
