# 跨小关装修、道具、Buff 与成功检查点：技术设计

需求见 [prd.md](prd.md)。一个大关进度对象贯穿四件事。不新建关间准备类型，不把选择写进 `CookingOrderSettlement`。

## 决定

大关进度只记录三样选择：当前装修标识、已解锁的 `DefinitionId` 列表、是否启用煮制加速。它不属于某一代 `LevelEpoch`。小关成功之后，这份进度连同交接后的厨房现场写成检查点。失败不写。

工位迁移改的是工序上的 `Station` 引用，以及「一个工位一个工序」那份索引。不新建 ET 父子关系，也不销毁厨房。

## 数据流

```text
上一小关 Ended + Success
  -> 确认并落盘结算列表（已有）
  -> 交接厨房，停在 Created
  -> 在 Created 选定装修、道具、Buff；选定前可改
  -> 装修原子迁移未完成工序
  -> 解锁道具按标准供应摆进延续厨房
  -> 写入大关检查点
       成功：锁定选择，进入可开始下一小关
       失败：不覆盖上一次成功检查点，调用方留在成功结算之后
  -> 调用方自行 CreateSuccessor / Start

失败重开
  -> 不写检查点
  -> 标准供应重建，并摆上当前进程里还没锁定失败清掉的解锁道具
  -> 选择仍可修改
```

## 边界

| 对象 | 责任 | 不负责 |
|---|---|---|
| 大关进度 | 记住装修、解锁定义、煮制加速；成功后锁定 | 算钱，生成顾客 |
| 厨房 | 在 `Created` 接受一次工位迁移，并把解锁道具摆进现场 | 决定候选列表 |
| 检查点文件 | 保存锁定进度和交接后的厨房现场 | 保存订单、结算条、NPC |
| 宿主 | 只在成功收口且结算已确认后允许写入 | 自动进入下一关 |

## 契约

- 装修候选、烤箱定义、煮制缩短比例都来自现有内容或测试夹具，不把数字写死在宿主里。缩短后的所需 tick 用整数，至少为 1。已经开始的工序不重算。
- 迁移和摆放要么整次成功，要么整次不变。中途发现工位冲突时，不留下一半工序已经改挂、一半还在旧工位。
- 检查点文件与结算列表文件分开。读到坏的检查点不影响已经落盘的结算列表。
- 检查点里的厨房现场复用成功交接已经保留的那一组字段，不另发明第三套厨房快照。

## 不采用

- 把装修做成销毁旧工位实体再新建。工序如果挂在被销毁的对象上，进度会丢。这正是 §5.3 要避开的做法。
- 解锁道具时重跑整份标准供应。成功路径的厨房必须延续，重跑会清掉半成品。
- 在检查点里放一个空的 NPC 列表来宣称前厅已保存。没有对象就不要写这个字段。

## 风险

- 内容文档里的烤箱供应位置如果和延续厨房里已有物品重叠，摆放必须拒绝并保持原样，不能覆盖锅或碗。
- Buff 若在工序开始时改写了内容目录里的配方本身，下一局没选 Buff 也会变快。缩短只作用在这一次新工序的 `RequiredTicks` 上。
- 失败重开「带着未锁定选择」容易被写成「失败也落盘」。检查点测试必须看到失败调用之后，目录里的上一次成功文件字节所代表的选择不变。
